01 / Enterprise GenAI · Data access

Natural-language access across complex scientific data

Designed an enterprise NL2SQL workflow for scientists who needed answers across many databases, schemas, and tables without relying on SQL specialists for every request. The system narrows context through metadata and domain vocabulary before generating and validating SQL.

NL2SQLRAGMetadata retrievalLLM guardrailsSQL validation
1,000+ users in scope · 60% faster retrieval turnaround · >47% direct execution accuracy in measured zero-shot evaluation
Problem → validation → outcome
Problem

Scientists had to locate the right database, tables, fields, and joins before they could even ask an analytical question.

Validation

Measured direct execution accuracy against baseline prompting and treated ambiguity as a first-class failure mode rather than forcing an answer.

Outcome

Created a reusable path for conversational access to enterprise data while reducing dependency on specialist support.

Key technical decisions

Retrieve schema before generating SQL

Hundreds of tables created too much irrelevant context. Narrowing the schema first improved grounding and made failure modes easier to evaluate.

Separate intent, schema, generation, and execution

Modular stages made the system safer to debug, test, and improve than a single end-to-end prompt.

Clarify instead of guessing

Ambiguous requests could trigger clarification rather than confidently executing an unsafe or semantically wrong query.

02 / Document intelligence · LLM extraction

Turning long reports into reusable structured data

Modernized extraction of pharmacokinetic parameters from long, inconsistent clinical study reports. The workflow combines document structure, targeted retrieval, an internal LLM service, and field-level checks to convert hard-to-query content into structured datasets.

Document AILLMsInformation extractionHuman validationStreamlit
800+ reports · >65% faster processing · 96% field-level extraction accuracy
Problem → validation → outcome
Problem

PK tables appeared in inconsistent formats and locations, making manual extraction slow and difficult to scale.

Validation

Started with manually reviewed examples, then used field-level accuracy and checks around units and ambiguous values.

Outcome

Created a repeatable route from unstructured reports to analysis-ready data while preserving review where uncertainty mattered.

Key technical decisions

Use document structure to reduce search space

Rather than prompting over an entire report, the workflow focused extraction on sections where PK information was most likely to appear.

Keep deterministic checks around the LLM

Units, missing values, and ambiguous fields needed explicit validation rather than trusting generative output alone.

Retain expert review for edge cases

Automation targeted repetitive extraction while reviewers remained responsible for uncertain or clinically nuanced cases.

03 / Cloud data platform · Scientific workflows

Modernizing a fragmented experiment archive

Designed a cloud archival workflow for roughly 20,000 experiment folders spread across legacy naming conventions. The solution connected scheduled ingestion, metadata services, APIs, and S3 storage so experiments could be archived reliably and discovered through searchable metadata.

AirflowFastAPIAWS S3MetadataIdempotent pipelines
20K+ experiment folders · transfer time reduced from ~15 to 7–8 minutes per 10 experiments · 57% lower storage cost
Problem → reliability → outcome
Problem

Historical experiments lived in inconsistent folder structures, limiting discoverability and increasing storage and transfer overhead.

Reliability

Used retries, logging, idempotency, scheduled ingestion, and metadata checks to make archival safe to repeat and monitor.

Outcome

Improved transfer efficiency, reduced storage cost, and created a more searchable long-term archive.

Key technical decisions

Separate metadata from raw storage

Searchability depended on reliable metadata services, not simply moving folders into lower-cost storage.

Design for re-runs

Idempotent pipeline behavior prevented duplicate archival when jobs were retried or interrupted.

Use orchestration, not manual transfer

Scheduled DAGs made ingestion observable and recoverable while reducing dependency on one-off scripts.

About

The common theme is simple: move from interesting technology to a system that solves a meaningful problem.
